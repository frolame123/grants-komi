# Развёртывание на сервере

Инструкция по развёртыванию, требуемая разделом 7 ТЗ.

## Что нужно

- VPS с физическим расположением дата-центра в России: в базе хранятся
  персональные данные граждан РФ (152-ФЗ), адрес электронной почты и ИНН;
- ресурсы: 2 vCPU, 4 ГБ оперативной памяти, 40 ГБ диска;
- доменное имя: сертификат Let's Encrypt на IP-адрес не выдаётся, а без
  сертификата не выполняется требование HTTPS;
- открытые порты 80 и 443 **до** переключения записи DNS, иначе проверка
  владения доменом не пройдёт и сертификат не будет выпущен.

## Порядок

### 1. Подготовка сервера

```bash
apt update && apt upgrade -y
apt install -y docker.io docker-compose-plugin git
systemctl enable --now docker
```

### 2. Исходный код

```bash
mkdir -p /opt && cd /opt
git clone https://github.com/frolame123/grants-komi.git
cd grants-komi
```

### 3. Настройки

```bash
cp .env.example .env
nano .env
```

Заполнить обязательно:

| Переменная | Значение |
|---|---|
| `DOMAIN` | доменное имя без протокола, например `grantykomi.ru` |
| `POSTGRES_PASSWORD` | пароль базы, сгенерированный, а не придуманный |
| `SECRET_KEY` | ключ подписи токенов |
| `PUBLIC_URL` | `https://` и домен — по нему строятся ссылки в письмах |
| `DATABASE_URL` | строка подключения с тем же паролем базы |

Ключ подписи токенов генерируется командой:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

### 4. Запуск

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Миграции применяются автоматически при старте контейнера приложения.
Первый запуск занимает несколько минут: собираются оба образа.

Проверка:

```bash
docker compose -f docker-compose.prod.yml ps
curl -I https://<домен>/api/health
```

### 5. Первый администратор

Учётная запись создаётся регистрацией через интерфейс, затем повышается
в правах напрямую в базе — иначе первого администратора назначить некому:

```bash
docker compose -f docker-compose.prod.yml exec db \
  psql -U grants -d grants \
  -c "UPDATE app_user SET role='admin', status='active' WHERE email='ваш@адрес';"
```

### 6. Резервное копирование

```bash
chmod +x deploy/backup.sh
crontab -e
```

Добавить строку:

```
30 3 * * * /opt/grants-komi/deploy/backup.sh >> /var/log/grants-backup.log 2>&1
```

Копии складываются в `/var/backups/grants-komi`: суточные хранятся неделю,
недельные — месяц.

Восстановление из копии:

```bash
docker compose -f docker-compose.prod.yml exec -T db \
  pg_restore -U grants -d grants --clean --if-exists < /var/backups/grants-komi/daily/grants-2026-08-10.dump
```

## Обновление

```bash
cd /opt/grants-komi
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

Миграции применятся сами. При автоматическом развёртывании эти же команды
выполняет задание GitHub Actions при слиянии в ветку main.

## Что проверить после развёртывания

- сертификат выпущен: адрес открывается по `https://`, браузер не ругается;
- документация API доступна по `/api-docs`;
- регистрация проходит и письмо уходит (при настроенном SMTP) либо видно
  в журнале: `docker compose -f docker-compose.prod.yml logs backend`;
- прогон источника выполняется: раздел «Прогоны агрегации» в панели
  управления, кнопка «Опросить сейчас»;
- резервная копия создаётся: запустить `deploy/backup.sh` вручную.

## Перенос с другого сервера

1. За сутки до переключения снизить время жизни записи DNS до 300 секунд.
2. Снять копию базы: `pg_dump -Fc`.
3. Развернуть стек на новом сервере, восстановить копию, проверить работу по
   временному поддомену или по адресу сервера.
4. Переключить запись A. Порты 80 и 443 должны быть открыты заранее.
5. Старый сервер не гасить неделю — на случай отката.

## Автоматическое развёртывание

Задание `.github/workflows/deploy.yml` обновляет сервер при слиянии в ветку
`main`. Пока оно выключено — включается переменной репозитория.

### Что настроить на GitHub

Настройки репозитория → Secrets and variables → Actions.

Вкладка **Secrets** (значения не видны после сохранения):

| Имя | Значение |
|---|---|
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | пользователь для подключения |
| `DEPLOY_SSH_KEY` | закрытый ключ доступа |
| `DEPLOY_DOMAIN` | домен для проверки отклика после обновления |
| `DEPLOY_PORT` | порт SSH, если отличается от 22 |

Вкладка **Variables**:

| Имя | Значение |
|---|---|
| `DEPLOY_ENABLED` | `true` |

### Ключ доступа

Пару ключей создаёт владелец сервера у себя, закрытый ключ загружается в
секреты, открытый добавляется на сервер:

```bash
ssh-keygen -t ed25519 -C "github-actions" -f deploy_key
ssh-copy-id -i deploy_key.pub пользователь@адрес-сервера
```

Содержимое `deploy_key` целиком, включая строки начала и конца, помещается в
секрет `DEPLOY_SSH_KEY`. Файл после этого удаляется с рабочей машины.

### Что делает задание

1. подключается к серверу;
2. забирает изменения из ветки `main`;
3. пересобирает и перезапускает контейнеры — миграции применяются сами;
4. удаляет неиспользуемые образы, чтобы диск не заполнялся;
5. опрашивает служебный маршрут и завершается ошибкой, если сервер не
   ответил: молчаливо сломанная выкладка хуже явно упавшей.
